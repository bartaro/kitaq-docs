KITAQFC

1. KITAQFC와 GB 컴파일러의 관계

KITAQFC는 KITAQGB의 프런트엔드를 사용하여 NES·패미컴의 6502 계열 CPU용 코드를 생성합니다. GB ROM을 NES ROM으로 변환하는 도구는 아닙니다. 대상 기종의 화면, 음향, 메모리, 매퍼에 맞춰 프로그램을 작성하세요.

기록된 검사에서는 구조체 복사와 일반 함수 호출을 사용한 예제가 실행되었습니다. 다만 NES에서 do-while과 switch는 코드 생성 미지원 오류를 냈습니다. 구문 분석기가 문장을 읽을 수 있다는 사실만으로 해당 기종에서 사용할 수 있다고 판단해서는 안 됩니다.

2. 개발 환경과 빌드

powershell
MSBuild.exe .\kitaqfc\kitaqfc\kitaqfc.csproj /t:Build /p:Configuration=Release
.\kitaqfc\bin\Release\kitaqfc.exe --help

.NET Framework 4.8 Developer Pack과 Visual Studio Build Tools를 설치하고 Developer PowerShell을 사용하세요. 이후 명령은 kitaqfc 저장소에 복사된 실행 파일을 기준으로 합니다. 다른 위치에서 빌드했다면 경로를 바꾸세요. CHR 그래픽과 C 소스는 별도 입력입니다. 설명서의 font.chr는 저자의 ascii.c를 변환한 8KiB 파일입니다.

3. 첫 프로그램

c
#include "fc_common.h"
void main(void) {
    m_init();
    m_text(2, 5, "HELLO WORLD");
    m_number(42);
    while (1) { m_wait(); }
}
powershell
.\kitaqfc\kitaqfc.exe .\kitaq-docs\samples\fc_hello.c -I .\kitaq-docs\samples -I .\kitaqfc\lib --mapper=nrom --nes-chr=.\kitaq-docs\samples\font.chr -o .\out\hello.nes --kurosaki-metadata=.\out\hello.debug.json

HELLO WORLD와 042를 표시하는 예제입니다. m_wait는 VRAM 큐를 커밋하고 NMI를 기다린 뒤 스크롤을 복구합니다. PPUADDR를 통한 전송은 내부 스크롤 상태에도 영향을 주므로, 복구를 생략하면 글자가 화면 가장자리로 밀릴 수 있습니다. ‘화면 끄기 → 리소스 준비 → 화면 켜기 → NMI 동기화’ 순서를 익히세요.

4. 언어의 기본

GB편의 문장과 식을 공통 출발점으로 삼을 수 있습니다. FC에서는 unsigned char, unsigned short를 사용할 수 있고, core.h가 u8, u16, s8, s16을 정의합니다. fc.h는 여러 헤더를 모아 둔 통합 헤더입니다. 이쪽에서는 인수 없는 시작 함수를 void main(void)로 작성할 수 있습니다.

c
#include "core.h"
u8 clamp_score(u8 n) {
    if (n > 99) return 99;
    return n;
}

정수는 8비트·16비트 범위 안에서 사용하고, 배열 인덱스는 0부터 시작한다는 점을 기억하세요. 함수·포인터·구조체는 fc_aggregate.c, 산술은 fc_arithmetic.c, 반복문은 fc_control.c에서 연습할 수 있습니다. FC 프로그램에 CGB 레지스터나 GB 전용 내장 함수를 넣지 마세요.

5. 지원되지 않는 구문 바꾸기

c
// do { update(); } while (condition);
// の代わりに、必ず1回実行してから条件を見る。
while (1) {
    update();
    if (!condition) break;
}
// switchの単純な振り分けはif/elseで表せる。
if (state == 0) { title_update(); }
else if (state == 1) { game_update(); }
else { pause_update(); }

do-while 대신 루프 본문을 먼저 한 번 실행한 후 종료 조건을 검사할 수 있습니다. 단순한 switch 분기는 if/else 연결로 바꿀 수 있습니다. 위 코드는 설명용 조각이므로 update와 상태별 함수는 직접 준비하세요. 완성된 ROM 예제는 fc_control.c입니다.

재귀 호출, 간접 함수 호출, 가변 인수 함수가 데스크톱과 동일하게 지원된다고 가정하지 마세요. 현재 일부 scene/entity 콜백 API는 함수 포인터를 저장할 뿐 간접 호출하지 않습니다.

6. 메모리와 PPU

NES의 CPU 내부 RAM은 0x0000~0x07FF입니다. 0x0800 위의 미러 영역은 추가 RAM이 아닙니다. 6502 스택은 페이지 1을 사용하며, OAM 섀도와 큐도 별도의 영역을 예약합니다. --nes-local-ram=START:LENGTH, --nes-temp-ram=START:LENGTH는 맵 확인이 필요한 고급 설정입니다.

PPU는 CPU와 별도의 주소 공간을 사용합니다. CHR은 무늬, 네임테이블은 타일 배치, 속성 테이블은 팔레트 그룹, 팔레트는 색 코드를 담습니다. 배경 속성은 보통 16×16픽셀 영역에 적용되므로 GB의 타일 속성과 다르게 동작합니다.

7. NMI와 VRAM 큐

NMI는 화면 프레임 경계와 관련된 인터럽트입니다. 렌더링 중 대량으로 PPU에 직접 쓰면 화면이 깨질 수 있습니다. 초기화는 화면을 끈 상태에서 직접 수행하고, 평소 갱신에는 __vramq_put, __vramq_copy, __vramq_fill과 커밋을 사용하세요.

c
__vramq_put(0x2000 + 8 * 32 + 3, '4');
__vramq_commit();
__nmi_wait();
__scroll_set(0, 0);

큐 용량과 소스 데이터의 유효 기간을 확인하세요. 기본 NMI 처리기는 큐를 처리합니다. 사용자 정의 __nes_nmi를 작성한다면 필요한 큐 실행, OAM 처리, 레지스터 보존을 유지해야 합니다.

8. 매퍼와 ROM 구성

선택값입문 시의 용도
nrom고정 ROM을 쓰는 작은 예제
uxrom / cnrom / axrom간단한 PRG·CHR 전환
mmc1 / mmc3 / mmc5큰 프로그램과 매퍼 고유 기능
vrc6 / vrc7 / fme7뱅크 전환과 해당 확장 기능
fds디스크 이미지 출력

이 표는 컴파일러의 선택값 목록이며, 실기나 에뮬레이터의 구현 완성도 표가 아닙니다. --board=surom512는 특정 MMC1 보드 구성을 선택합니다. 파일 뒤를 채워 512KiB로 만드는 것만으로 그 구성이 성립하지는 않습니다. KUROSAKI의 보드 검사도 함께 이용하세요.

powershell
.\kitaqfc\kitaqfc.exe main.c --mapper=mmc3 --nes-chr=tiles.chr --mirroring=vertical -o .\out\game.nes --kurosaki-metadata=.\out\game.debug.json --emit-ai-metadata=.\out\build.json

--battery / --no-battery, CHR 용량, PRG 배치, 뱅크 간 호출이 보드 요구 사항과 맞는지 확인하세요. 매퍼나 미러링을 바꾼 뒤에는 ROM 생성뿐 아니라 시작 동작, 스크롤, 데이터 전환도 시험해야 합니다.

9. FDS, 확장 음원, 주변기기

FDS 개발에는 디스크 파일 배치, 시작 절차, 오버레이, 저장이 관계됩니다. fds_manifest_sample.json과 FDS 헤더를 참고하세요. 필요한 BIOS는 자신의 실행 환경에 별도로 준비해야 하며 공개 배포본에는 포함되지 않습니다.

VRC6·VRC7 음원 함수를 호출한다고 ROM의 매퍼 설정이 바뀌지는 않습니다. 사용하는 확장 음원에 맞는 매퍼를 선택하세요. 주변기기는 입력값, 연결 상태, 일반 컨트롤러 경로에 미치는 영향을 각각 확인해야 합니다.

10. 진단과 빌드 결과

KQ 진단과 symfind, src2asm, romdiff 같은 개발 명령은 GB판과 비슷합니다. 다만 GB에서 상속한 도움말 항목 중에는 NES에 구현되지 않은 기능도 있을 수 있습니다. FC API 사전은 FC 소스와 헤더에서 별도로 수집했습니다.

직접 PPU 조작에 대한 KQ2421 같은 경고는 화면을 끈 초기화에서도 나올 수 있습니다. 경고를 없애려고 안전한 초기화 순서를 깨뜨리지 마세요. 렌더링 시점과 실행 로그를 확인해야 합니다. ‘오류 없음’과 ‘경고 없음’은 서로 다른 결과입니다.

소스 위치

컴파일러 소스와 프로젝트 파일은 저장소 안의 같은 이름을 가진 하위 폴더에 있습니다. 실행 파일은 저장소 루트에, 라이브러리는 lib/에 있습니다. 프로젝트 경로와 빌드 요구 사항은 폴더 구성 안내를 참고하세요.
