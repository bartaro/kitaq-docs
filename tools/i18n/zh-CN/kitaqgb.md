## 1. 认识 KITAQGB
KITAQGB 是从 Zachtronics 的 NORCAL 发展而来的 GB/CGB C 语言编译器。

{{ORIGIN}}

它读取 C 文件，生成 CPU 指令，再封装成主机可读取的 ROM。它的语言、库和调用约定与桌面 C 编译器并不完全相同。

GB 使用 8 位 CPU，内存有限。画面主要由 8×8 像素的图块组成；精灵是可独立定位的小图像。文字同样需要图块，不能假定系统自带通用文字显示。本例采用作者的 `ascii.c`，按 GB 的 ASCII 顺序重新排列，但不改变字形位图；FC 版则转换为 NES CHR 布局。

## 4. 基本语法与类型
语句以 `;` 结尾，多条语句用 `{ }` 分组。`//` 开始行注释，`/* ... */` 表示块注释，名称区分大小写。入口请写成 `void main()`。**本 GB 版本中的 `void main(void)` 会产生语法错误**，不要原样照搬 FC 的入口声明。

| 类型 | 含义与范围 |
| --- | --- |
| `u8` | 无符号 8 位整数，0～255 |
| `s8` | 有符号 8 位整数，-128～127 |
| `u16` | 无符号 16 位整数，0～65535 |
| `s16` | 有符号 16 位整数，-32768～32767 |
| `void` | 无返回值 |
| `T*` | 指向 T 类型数据的指针 |

入门时建议使用这些短类型名。不要假定 `int`、`long`、`float`、`double` 和标准头文件与桌面环境相同。本版 `char` 是无符号 8 位数据；需要负数时请明确使用 `s8` 或 `s16`。

{{CODE:3}}

`(u16)` 是强制类型转换。小类型已经溢出的值，即使再赋给大变量，也无法找回丢失的位；应在计算前扩大操作数的类型。小数单位的移动可使用定点数库。

## 5. 表达式与运算符
| 类别 | 运算符 | 示例或含义 |
| --- | --- | --- |
| 算术 | `+ - * / %` | `n / 10` 求整数商，`n % 10` 求余数 |
| 比较 | `== != < <= > >=` | `lives == 0` 判断相等 |
| 逻辑 | `! &&` / `||` | 非、两个条件都成立、任一条件成立 |
| 位运算 | `&` / `|` / `^ ~ << >>` | 按钮掩码及其他位集合 |
| 赋值 | `= += -=` 等 | `x += 1` 更新数值 |
| 自增自减 | `++ --` | `i++` 增加 1 |
| 条件选择 | `condition ? A : B` | 根据条件选择一个值 |
| 指针 | `&variable` / `*p` | 取得地址或访问指向的数据 |

请区分 `=` 和 `==`。复杂表达式用括号写清意图，不要把过多函数调用和副作用挤在一条语句里。避免除以零和数组越界。`sizeof` 返回字节数，`offsetof` 返回结构体成员的偏移。

### 表达式结果与求值
比较运算符 `==`、`!=`、`<`、`<=`、`>`、`>=` 和逻辑运算符 `!`、`&&`、`||` 以 0 表示假、1 表示真。结果可存入 `u16`、传参、返回或参加算术。例如 `score = 500 + (lives != 0);` 在还有生命时得到 501，否则为 500。

`&&` 左操作数为零时跳过右操作数；`||` 左操作数非零时跳过右操作数。在 `pointer != 0 && pointer->active != 0` 中，空指针会阻止成员访问。16 位值的两个字节都参加真值判断，因此 256 为真。按位 `&` 和 `|` 不短路。

`++value` 返回更新后的值，`value++` 返回原值，也可操作数组元素、解引用指针及结构体成员。`buffer[index()]++` 只调用一次 `index()`。对于 `u16 *p`，`p++` 前进两字节到下一个元素，`(*p)++` 则递增所指向的值。

`sizeof(array)` 给出整个数组的字节数，`sizeof(pointer)` 为 2。对于 `u16 values[9];`，`sizeof(values)` 为 18。此规则涵盖 ROM 数组、局部数组及数组成员。`sizeof(function())` 检查返回类型，不调用函数。

函数声明和定义的参数类型及顺序必须一致，参数名可以不同；函数体使用定义中的名称。例如 `u8 next(u8 input);` 可定义为 `u8 next(u8 value) { return (u8)(value + 1); }`。参数和局部变量会遮蔽同名全局变量。

用 `?:` 选择数组或字符串，会产生指向所选元素类型的指针，可直接传参，例如 `show(ready ? "READY" : "WAIT");`。对于 u16 数组 a 和 b，`(ready ? a : b) + 1` 前进两字节，指向所选数组的第二个元素，不复制数组。

`condition ? yes : no` 先计算条件，再只计算选中的分支。条件和分支可含可变移位数，例如 `on = (pattern & (0x80 >> bit)) != 0 ? 4 : 2;` 根据所选位得到四或二。被 `&&` 或 `||` 跳过的右操作数中的函数也不会调用。for 循环中的 continue 先执行一次更新表达式，再重算条件；while 和 do ... while 中则进入条件判断。

## 6. 分支与循环
{{CODE:4}}

`break` 离开循环或 switch，`continue` 进入下一轮循环，`return` 结束函数。需要从一个 switch case 继续执行下一个时，请明确写出 `fallthrough;`；隐式贯穿会触发诊断。完整程序见 `gb_control.c`。

## 7. 函数、数组与结构体
{{CODE:5}}

数组下标从 0 开始，四元素数组的合法下标为 0～3。`player.x` 访问成员，`pointer->x` 通过指针访问成员。解析器接受结构体、联合体和枚举，但布局取决于类型以及 `__packed` / `__aligned` 属性。与硬件或二进制格式交换数据前，应检查 `sizeof`。

默认 Legacy ABI 将参数和局部存储放在固定位置。不要假定具备桌面式递归或中断重入能力。`__stackcall` 和 `--abi=stack` 是高级调用约定选项；混用约定时应检查 ABI 报告并验证执行。`--abi=stack` 不支持通过函数指针调用回调。请按构建命令使用默认 Legacy ABI，构建完整 system 和 scene 回调示例。

## 8. 多文件与预处理器
类型、常量、声明放在头文件，函数体放在 `.c` 文件。使用 `#pragma once` 或头文件保护宏避免重复包含。条件编译支持 `#define`、`#undef`、`#if`、`#ifdef`、`#ifndef`、`#elif`、`#else`、`#endif`。

{{CODE:6}}

`-I` 添加头文件搜索目录。包含头文件并不等于链接实现，还要在构建命令中列出所需 `.c` 文件。按需选择源文件；把全部库文件无差别加入，可能造成寄存器定义或中断处理程序重复。

## 9. ROM、内存与分页
ROM 存代码和常量，WRAM 存变量，VRAM 存图像，OAM 存精灵描述。切换 bank 会改变 CPU 地址映射到哪一块实际内存。单独一个 16 位指针无法标识另一 bank 的数据。

{{CODE:7}}

`__prg_rom` 将数据放入 ROM；`__location(0xFF40)` 等属性指定固定地址，`__wram` / `__hram` 指定内存区域。使用 `#pragma bank` 或 `#pragma fixed_bank` 时，请检查映射文件，确保中断使用的代码和数据始终可访问。

{{CODE:8}}

`--cgb=dmg` 声明 DMG 软件，`--cgb=cgb` 声明双模式软件，`--cgb=cgb_only` 声明 CGB 专用软件。双模式游戏必须先识别硬件，再使用 CGB 专用功能。ROM 头标志不会替你实现游戏内部的双模式逻辑。

## 10. 安全更新图像
VBlank 是显示帧之间的空白期。时机不当的 VRAM/OAM 写入可能导致画面损坏或更新丢失。初始化素材应在关闭显示时加载，常规更新应使用安全内建函数或 VRAM 队列。带 `_unsafe`、`_fast` 的函数需要调用方保证安全传输时段。

OAM DMA 缓冲区须按 256 字节边界对齐。GB 的 `__oam_dma` 接收源地址；FC 的同名内建函数没有参数，二者不能混用。

## 11. 构建选项与输出文件
`-o` 选择输出，`-O0` / `-O1` 选择优化级别，`--profile=dev|release|test` 选择设置组合。`--no-disasm` 关闭反汇编输出；`--debug-out=...`、`--trace-out=...` 指定调查资料的位置。根据快速构建或详细排查的需要选择输出量。

{{CODE:9}}

`.map` 记录名称和布局，`.funcsizes.txt` 记录函数大小，`.dbg2.json` / `.source_map.txt` 关联执行位置与源码，`.build_report.json` 汇总构建结果。明确生成 `--emit-ai-metadata` JSON，可使 SARAKURA 的输入关系更清楚。

## 12. 从第一个错误读起
先读首个错误的文件名、行号和 KQ 诊断编号；后续错误可能只是第一个语法错误的连锁结果。未定义符号应检查声明、实现以及是否加入构建。ROM 超出容量时，检查素材大小、函数大小和 bank 布局。
