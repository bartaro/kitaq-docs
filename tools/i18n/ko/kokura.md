## 빌드된 Windows CLI
저장소 루트에 `kokura-cli.exe`가 들어 있습니다. ZIP을 내려받아 실행 파일과 라이선스 문서를 함께 보관하세요. Windows x64용 CLI는 실행 시 Rust, Python, .NET 설치가 필요하지 않습니다. 아래 빌드 절차는 소스에서 다시 빌드할 때 사용합니다. 독자적으로 작성한 프로젝트 코드는 DAISUKE OBA가 MIT로 제공합니다. 의존 라이브러리의 조건은 `BINARY_NOTICES.md`와 `licenses/`에 유지합니다.

## 1. KOKURA의 역할
KOKURA는 GB/CGB 소프트웨어를 에뮬레이션하고 화면, 음향, CPU 실행, 메모리, 뱅크, 입력, 진단 이벤트를 기록합니다. 현재 실행 파일 이름은 `kokura-cli.exe`입니다. 과거 자료의 `kokuradbg`가 이번 배포본의 파일 이름이라고 생각하지 마세요.

## 3. DMG와 CGB 선택
`--hardware auto`가 기본값이며 `dmg`, `cgb`를 명시할 수도 있습니다. 양쪽 모드용 ROM은 두 모드 모두 시험하세요. CGB 전용 ROM이 DMG에서 시작을 거부하는 것만으로 에뮬레이터 오류라고 볼 수는 없습니다.

## 4. 입력 전달
`--input`은 버튼 조합을 계속 누르고, `--input-seq`는 시간에 따른 입력 순서를 전달합니다. 버튼 이름은 `A,B,START,SELECT,UP,DOWN,LEFT,RIGHT`이며, 모두 놓는 구간에는 `NONE`을 사용합니다. PowerShell에서는 세미콜론이 포함된 순서를 따옴표로 감싸세요.

{{CODE:2}}

새로 누르는 순간을 검사할 때는 버튼을 놓는 구간도 넣어야 합니다. A를 120프레임 동안 누르는 것과 120번 누르는 것은 다릅니다. 입력 카운터 예제에서는 위 순서로 카운트가 한 번 증가해야 합니다.

## 5. 화면, 영상, 음향 기록
`--png`는 마지막 화면을 저장합니다. `--screenshot`과 `--screenshot-frames`는 지정 프레임을 캡처하고, `--record-video`는 영상, `--record-wav`는 음향을 기록합니다. APU를 쓰지 않는 hello 프로그램의 WAV가 무음인 것은 정상입니다.

{{CODE:3}}

범위는 `start:end`로 지정합니다. 불러온 상태의 누적 프레임과 이번 실행 안의 위치를 구별할 수 있도록 보고서를 보관하세요. 실제 소리, 음높이, 끊김, 클리핑은 각각 확인해야 합니다. 에뮬레이터 녹음만으로 실기와 샘플 단위까지 일치한다고 입증할 수는 없습니다.

## 6. 상태 저장과 재개
{{CODE:4}}

일반적으로 같은 ROM과 같은 에뮬레이터 버전을 사용하세요. 에뮬레이터 상태와 게임 자체의 세이브 데이터는 다릅니다. CLI의 KQS 파일과 C API의 JSON 상태도 별도 형식이므로 확장자만 바꿔서는 서로 사용할 수 없습니다.

## 7. 심볼과 메모리 관찰
ROM 옆의 `.map`, `.source_map.txt`, `.dbg2.json`, `.build_report.json` 같은 보조 파일을 자동으로 찾을 수 있습니다. 반드시 해당 ROM과 같은 빌드에서 나온 파일을 함께 두세요. 다른 빌드의 자료가 섞이면 관찰 결과를 잘못 해석할 수 있습니다.

{{CODE:5}}

`wram`은 관찰 창 이름, 0xC000은 시작 주소, 0x40은 길이입니다. 좁은 범위를 보면 변한 변수를 찾기 쉽습니다. `--watch-baseline-mode`는 초기값, 직전 프레임, 이름 붙인 기준 상태 중 비교 대상을 선택합니다.

## 8. 중단 조건, 리플레이, 역분석
`--breakpoint`, `--watchpoint`, `--run-until`, `--snapshot-at`은 조건에 따라 멈추거나 상태를 저장합니다. 각 옵션의 인수 문법은 서로 다르므로 아래 참조와 실제 도움말을 확인하세요.

{{CODE:6}}

처음 달라지는 지점을 찾은 뒤 그 주변의 짧은 구간을 자세히 관찰하세요. `--decompile-out`은 의사 코드와 제어 흐름 정보, `--disassemble-out`은 CPU 명령을 출력합니다. 디컴파일이 원래의 C 코드나 변수 이름을 완벽히 복원하지는 않습니다.

## 9. SARAKURA에 진단 전달
{{CODE:7}}

KOKURA의 `--emit-diagnostics`에는 `out/gb_events.jsonl` 같은 **JSONL 파일 이름**을 지정합니다. 일반 실행 보고서 JSON이나 CPU 트레이스 JSONL은 진단 이벤트 입력과 다른 자료입니다.

## 10. 통신 작업
`pair`는 두 기기, `four_player_adapter`는 호스트가 통신 상대를 선택하는 논리 구성, `dmg07`은 물리 DMG-07 프로토콜을 모델링합니다. `--link-job`으로 작업 JSON을 전달하거나 `--link-topology`, `--link-session`으로 세션을 설정하세요.

{{CODE:8}}

각 ROM에 통신 처리가 구현되어 있어야 합니다. 평범한 hello 프로그램 두 개를 실행하는 것은 통신 라이브러리 시험이 아닙니다. 세션별 ROM, 슬롯, 입력, 상태를 기록하고, 실제 기기의 어떤 동작을 아직 확인하지 못했는지도 구분하세요.

## 11. 외부 프로그램과 연동
공개 C ABI는 `kokura-capi`에 있습니다. Python에서는 제공된 브리지와 Python 크레이트를 이용할 수 있습니다. 연동 문제를 조사하기 전에 최소한의 CLI 재현 예를 먼저 만드세요.

## 12. 보고서를 읽는 순서
실행 프레임과 중단 이유를 먼저 보고, 화면, 입력 결과, 소리, 오류·경고, 프로파일 순서로 확인하세요. 입력 없이 타이틀 화면을 오래 관찰하면 정지 화면이나 반복 PC 경고가 자연스럽게 나올 수 있습니다. 모든 경고를 곧바로 오작동으로 취급하지 말고, 의도한 장면과 대조하세요.
