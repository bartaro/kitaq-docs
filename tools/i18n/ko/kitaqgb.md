## 1. KITAQGB 알아보기
KITAQGB는 Zachtronics의 NORCAL에서 발전한 GB/CGB용 C 계열 컴파일러입니다.

{{ORIGIN}}

C 파일을 읽어 CPU 명령을 생성하고 ROM으로 묶습니다. 문법, 라이브러리, 호출 규약은 데스크톱용 C 컴파일러와 다릅니다.

GB는 8비트 CPU와 작은 메모리를 사용합니다. 화면은 주로 8×8픽셀 타일로 구성하며, 스프라이트는 독립적으로 배치하는 작은 이미지입니다. 문자도 타일 그림이 필요합니다. 별도 준비 없이 어떤 문자든 표시하는 기능이 있다고 가정하지 마세요. 예제는 저자의 `ascii.c` 글리프를 비트 변경 없이 GB용 ASCII 순서로 재배열합니다. FC판은 같은 모양을 NES CHR 형식으로 바꿉니다.

## 4. 기본 문법과 자료형
문장은 `;`로 끝내고 여러 문장은 `{ }`로 묶습니다. `//`는 한 줄 주석, `/* ... */`는 블록 주석입니다. 이름은 대소문자를 구분합니다. 시작 함수는 `void main()`으로 작성하세요. **이 GB판에서는 `void main(void)`가 구문 오류를 일으키므로** FC의 시작 함수 선언을 그대로 복사하면 안 됩니다.

| 자료형 | 의미와 범위 |
| --- | --- |
| `u8` | 부호 없는 8비트 정수, 0~255 |
| `s8` | 부호 있는 8비트 정수, -128~127 |
| `u16` | 부호 없는 16비트 정수, 0~65535 |
| `s16` | 부호 있는 16비트 정수, -32768~32767 |
| `void` | 반환값 없음 |
| `T*` | T형 데이터를 가리키는 포인터 |

처음에는 이 짧은 자료형 이름을 사용하세요. `int`, `long`, `float`, `double`, 표준 헤더가 데스크톱과 같다고 가정하지 마세요. 이 버전의 `char`는 부호 없는 8비트 값입니다. 음수가 필요하면 `s8`이나 `s16`을 명시하세요.

{{CODE:3}}

`(u16)`은 형 변환입니다. 작은 자료형에서 이미 넘친 값을 큰 변수에 대입해도 잃어버린 비트는 돌아오지 않습니다. 계산 전에 피연산자의 폭을 넓혀야 합니다. 소수 단위 이동에는 고정소수점 라이브러리를 사용하세요.

## 5. 식과 연산자
| 종류 | 연산자 | 예 또는 의미 |
| --- | --- | --- |
| 산술 | `+ - * / %` | `n / 10`은 정수 몫, `n % 10`은 나머지 |
| 비교 | `== != < <= > >=` | `lives == 0`은 같은지 검사 |
| 논리 | `! &&` / `||` | 부정, 두 조건 모두 참, 어느 하나가 참 |
| 비트 | `&` / `|` / `^ ~ << >>` | 버튼 마스크 등 비트 집합 처리 |
| 대입 | `= += -=` 및 관련 형태 | `x += 1`은 값 갱신 |
| 증감 | `++ --` | `i++`는 1 증가 |
| 선택 | `condition ? A : B` | 조건에 따라 값 선택 |
| 포인터 | `&variable` / `*p` | 주소 얻기 또는 가리키는 값 접근 |

`=`와 `==`를 구별하세요. 복잡한 식은 괄호로 의도를 드러내고, 한 문장에 함수 호출과 부수 효과를 과도하게 섞지 마세요. 0으로 나누거나 배열 범위를 벗어나지 않도록 주의하세요. `sizeof`는 바이트 크기, `offsetof`는 구조체 멤버의 오프셋을 구합니다.

## 6. 분기와 반복
{{CODE:4}}

`break`는 반복문이나 switch를 벗어나고, `continue`는 다음 반복으로 넘어가며, `return`은 함수를 끝냅니다. switch의 다음 case로 의도적으로 이어서 실행하려면 `fallthrough;`를 명시하세요. 암묵적인 이어 실행은 진단 대상입니다. 완성된 예제는 `gb_control.c`입니다.

## 7. 함수, 배열, 구조체
{{CODE:5}}

배열 인덱스는 0부터 시작합니다. 원소가 4개면 0~3만 유효합니다. `player.x`는 멤버를 선택하고 `pointer->x`는 포인터를 통해 멤버에 접근합니다. 구조체, 공용체, 열거형을 구문 분석하지만, 실제 배치는 자료형과 `__packed` / `__aligned` 속성에 따라 달라집니다. 하드웨어나 바이너리 파일과 데이터를 공유하기 전에 `sizeof`를 확인하세요.

기본 Legacy ABI는 인수와 지역 저장소를 고정 위치에 둡니다. 데스크톱처럼 재귀 호출이나 인터럽트 재진입이 가능하다고 가정하지 마세요. `__stackcall`, `--abi=stack`은 고급 호출 규약 설정입니다. 규약을 혼용한다면 ABI 보고서와 실제 실행을 확인하세요.

## 8. 여러 파일과 전처리기
자료형·상수·선언은 헤더에, 함수 본문은 `.c` 파일에 둡니다. `#pragma once`나 인클루드 가드로 중복 포함을 막으세요. 조건부 컴파일에는 `#define`, `#undef`, `#if`, `#ifdef`, `#ifndef`, `#elif`, `#else`, `#endif`를 사용할 수 있습니다.

{{CODE:6}}

`-I`는 헤더 검색 폴더를 추가합니다. 헤더를 포함하는 것만으로 구현이 링크되지는 않습니다. 필요한 `.c` 파일을 빌드 명령에 나열하세요. 모든 라이브러리를 무조건 추가하면 레지스터 정의나 인터럽트 처리기가 중복될 수 있습니다.

## 9. ROM, 메모리, 뱅크
ROM에는 코드와 상수, WRAM에는 변수, VRAM에는 그래픽, OAM에는 스프라이트 정보가 들어갑니다. 뱅크 전환은 CPU 주소에 보이는 실제 메모리를 바꾸는 기능입니다. 16비트 포인터 하나만으로는 다른 뱅크의 데이터를 특정할 수 없습니다.

{{CODE:7}}

`__prg_rom`은 데이터를 ROM에 배치합니다. `__location(0xFF40)` 같은 속성은 고정 주소를, `__wram` / `__hram`은 메모리 영역을 지정합니다. `#pragma bank`, `#pragma fixed_bank`를 쓸 때는 맵 파일을 확인하고 인터럽트가 사용하는 코드와 데이터에 항상 접근할 수 있게 하세요.

{{CODE:8}}

`--cgb=dmg`는 DMG용, `--cgb=cgb`는 양쪽 모드용, `--cgb=cgb_only`는 CGB 전용임을 선언합니다. 양쪽 모드를 지원하는 게임은 CGB 전용 기능을 쓰기 전에 하드웨어를 감지해야 합니다. 헤더의 플래그가 게임 내부의 모드별 처리를 대신 구현해 주지는 않습니다.

## 10. 안전한 그래픽 갱신
VBlank는 화면 프레임 사이의 공백 기간입니다. 적절하지 않은 시점에 VRAM이나 OAM에 쓰면 화면이 깨지거나 갱신이 누락될 수 있습니다. 초기 리소스는 화면을 끈 상태에서 읽어 들이고, 매 프레임 갱신에는 안전한 내장 함수나 VRAM 큐를 사용하세요. `_unsafe`, `_fast` 함수는 호출 측에서 안전한 전송 시점을 보장해야 합니다.

OAM DMA 버퍼는 256바이트 경계에 맞춰 정렬하세요. GB의 `__oam_dma`에는 소스 주소를 전달하지만, 같은 이름의 FC 내장 함수는 인수가 없습니다.

## 11. 빌드 명령과 출력 파일
`-o`는 출력 경로, `-O0` / `-O1`은 최적화 수준, `--profile=dev|release|test`는 설정 묶음을 선택합니다. `--no-disasm`은 역어셈블 출력을 생략하며, `--debug-out=...`, `--trace-out=...`는 조사 자료의 출력 위치를 정합니다. 빠른 빌드와 상세 조사에 맞춰 필요한 출력량을 선택하세요.

{{CODE:9}}

`.map`은 이름과 배치, `.funcsizes.txt`는 함수 크기, `.dbg2.json` / `.source_map.txt`는 실행 위치와 소스의 대응, `.build_report.json`은 빌드 요약을 담습니다. `--emit-ai-metadata`로 JSON을 명시적으로 출력하면 SARAKURA에 연결하기 쉽습니다.

## 12. 첫 오류부터 읽기
첫 오류의 파일 이름, 줄 번호, KQ 진단 번호부터 확인하세요. 뒤의 오류는 첫 문법 오류 때문에 연달아 발생했을 수 있습니다. 정의되지 않은 심볼은 선언, 구현, 빌드 명령의 소스 목록을 점검하세요. ROM 용량 초과라면 리소스·함수 크기와 뱅크 배치를 살펴보세요.

{{CODE:10}}

## 13. 인라인 어셈블리
`__asm { ... }`에는 KITAQGB의 명령어 이름을 사용합니다. 다른 GB 어셈블러의 소스를 임의로 받아들인다는 뜻은 아닙니다. 내부 표기에는 `LD_A_IMM` 같은 이름이 있습니다. 인수, 반환값, 보존 레지스터, 스택 동작을 이해한 뒤 사용하세요. 부록에 명령어 표기와 피연산자 형식이 정리되어 있습니다.

{{CODE:11}}

## 소스 위치
컴파일러 소스와 프로젝트 파일은 저장소 안의 같은 이름을 가진 하위 폴더에 있습니다. 실행 파일은 저장소 루트에, 라이브러리는 `lib/`에 있습니다. 프로젝트 경로와 빌드 요구 사항은 [폴더 구성 안내](../GITHUB_SETUP.md)를 참고하세요.
