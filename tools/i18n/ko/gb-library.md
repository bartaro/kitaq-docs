## 2. 게임의 한 프레임 구성
`system_init`는 프레임 관리를 초기화합니다. `system_wait_vblank`는 대기 후 소프트웨어 프레임 번호를 증가시킵니다. GB의 VBlank 콜백은 대기 함수가 협력 방식으로 호출합니다. 등록만으로 하드웨어 인터럽트 처리기가 설치되는 것은 아닙니다.

1. 입력을 한 번 갱신합니다.
2. 이동, 충돌, 게임 상태를 계산합니다.
3. 그리기 명령과 OAM을 준비합니다.
4. VBlank 중 갱신 내용을 적용합니다.
5. 선택한 드라이버 구성에 맞춰 음악을 진행합니다.

`vram_flush`, `sprite_flush_oam`처럼 내부에서 기다리는 함수를 함께 쓰면 게임 갱신 한 번에 두 프레임을 기다릴 수 있습니다. 직접 대기한 뒤에는 대응하는 `_now` 함수를 쓸 수 있지만, 호출 측에서 시점 조건을 보장해야 합니다.

## 3. 입력과 반복 입력
`input_down(mask)`는 누르고 있는 버튼, `input_pressed(mask)`는 새로 누른 버튼, `input_released(mask)`는 놓은 버튼을 검사합니다. `input_repeat(mask)`는 메뉴용 반복 입력을 제공합니다. 상태는 `input_update()`에서 갱신됩니다. 한 프레임에 여러 번 갱신하면 누른 순간의 정보가 사라질 수 있습니다.

| 버튼 | 마스크 |
| --- | --- |
| 오른쪽, 왼쪽, 위, 아래 | 0x01 / 0x02 / 0x04 / 0x08 |
| A, B, SELECT, START | 0x10 / 0x20 / 0x40 / 0x80 |

`gb_input.c`는 A를 누른 횟수를 셉니다. 길게 눌러도 계속 증가하지 않는지 확인한 다음, `input_pressed`를 `input_down`으로 바꿔 차이를 살펴보세요.

## 4. 배경, 문자, VRAM
`vram_queue_bg_tile`은 타일 하나, `vram_queue_bg_rect`는 사각 영역, `vram_queue_bg_block`은 배열 전송을 큐에 넣습니다. 반환값과 `vram_get_overflowed()`로 용량 초과를 확인하세요. 큐가 소스 포인터를 보관하는 경우, 적용이 끝날 때까지 내용을 바꾸지 말고 메모리와 뱅크 접근을 유지해야 합니다.

`text.c`, `menu.c`는 `rpg.h`에 선언된 문자, 선택지, 창 기능을 구현합니다. 문자와 타일의 대응은 VRAM에 올린 글꼴과 맞춰야 합니다. 설명서의 `m_text` 도우미와 자동으로 같은 대응을 쓰는 것은 아닙니다.

## 5. 스프라이트와 애니메이션
`sprite_init`, `sprite_alloc`, `sprite_set_tile`, `sprite_set_pos`부터 사용해 보세요. GB는 전체 40개, 한 주사선 10개까지 스프라이트를 표시하므로 총수뿐 아니라 가로로 몰리는 정도도 고려해야 합니다. `sprite_warn_scanline_overflow`, `sprite_max_scanline_count`로 배치를 점검할 수 있습니다.

`MetaSpritePart`는 상대 OBJ 배치, `SpriteAnim`은 타일 프레임과 갱신 간격을 정의합니다. `metasprite_draw`가 그릴 부품 수를 할당한 OBJ 슬롯과 맞추세요. `gb_sprite.c`의 A는 문자 타일을 스프라이트로 사용하는 예입니다.

## 6. 색, 스크롤, 래스터 효과, 카메라
`cgb_bg_rgb`, `cgb_obj_rgb`의 RGB 인수 범위는 0~31이며 0~255가 아닙니다. `CGB_RGB15`는 이를 16비트 값에 포장합니다. 고수준 CGB 팔레트 도우미는 DMG에서는 아무것도 하지 않도록 설계되었습니다.

`Scroll_SetBg`는 배경, `Scroll_SetWindow`는 윈도 위치를 정합니다. 카메라 모듈은 월드 좌표에서 화면에 보일 범위를 계산합니다. 카메라의 고정소수점 단위와 정수 화면 픽셀을 구별하세요.

`raster.c`는 구간별 스크롤 표와 주사선별 가로 왜곡을 만듭니다. `Scroll_SplitCommit`은 VBlank·STAT 벡터를 사용합니다. 음악과 스크롤의 별도 처리기가 같은 벡터를 각각 소유하게 하지 말고, 필요하면 공통 디스패처를 두세요.

## 7. 음악과 효과음
`audio_hwregs_gb.c`, `audio.c`, 게임 소스 순서로 컴파일합니다. 게임에서 NR10~NR52를 이미 선언한다면 중복 정의를 추가하지 마세요. `Audio_Init` 뒤에는 보통 프레임마다 `Audio_Update`를 한 번 호출합니다.

`Audio_PlayMusic(bank,song)`은 음악 뱅크를 명시합니다. `Audio_PlaySFXBanked`는 다른 뱅크의 효과음을 재생합니다. 같은 물리 채널을 쓰는 효과음은 우선순위로 조정합니다. GB의 물리 음원 채널은 CH1, CH2, CH3, CH4의 네 개입니다.

음악 스트림의 `AUDIO_CMD_NOTE`, `AUDIO_CMD_SET_INST`는 기존 순서인 **0=CH1, 1=CH2, 2=CH4, 3=CH3**을 유지합니다. 일반 API 채널 상수와 혼동하지 마세요. 현재 헤더의 최댓값은 `AUDIO_NOTE_MAX=67`입니다.

기본 CH1 효과음 스트림은 프레임마다 음표·음량 쌍을 읽고 음표 0에서 끝납니다. CH3는 다른 표식과 형식을 사용합니다. `gb_sound.c`를 참고하세요. 페이드는 `Audio_Update`에서 진행되므로 갱신을 멈추면 페이드도 멈춥니다.

## 8. VBlank IRQ 음악
`audio_vblank.c`는 별도의 재생 형식을 사용합니다. 시간 지정 레코드는 `delay, ch2_note, ch1_note, ch3_note, ch4_noise_param`의 5바이트로 구성됩니다. 드라이버는 직접 접근할 수 있는 곡을 읽거나 WRAM 큐에서 데이터를 꺼냅니다. 공개 라이브러리에는 큐를 채우는 함수가 없으므로 게임에서 공급 코드를 작성하고 ISR과 쓰기 작업을 동기화해야 합니다. `LOOP`는 직접 접근 방식에서만, `IMMEDIATE`는 큐 방식에서만 인식됩니다. 일반 `audio.c` 스트림을 그대로 전달할 수는 없습니다.

## 9. 고정소수점, 물리, 3D
`fixed.h`의 Q8.8에서는 256이 1.0, 128이 0.5입니다. `gb_fixed.c`는 `fix_from_int`, `fix_mul`, `fix_to_int`를 사용합니다. 넘침을 피하려면 계산을 구현하기 전에 값의 범위를 정하세요.

`physics2d`는 사각형, `physics2d_circle`은 원, `physics3d`는 3D AABB를 처리합니다. 호출 측에서 world와 body 배열을 준비하고 초기화한 뒤 속도나 중력을 설정하고 step을 호출하세요. 위치와 스텝당 속도의 단위를 일관되게 사용해야 하며, 라이브러리가 자동으로 픽셀 단위로 환산하지는 않습니다. 원 예제는 위치 40과 속도 2를 사용합니다. 역질량 0은 정적 물체를 뜻합니다. 각 계수의 표현과 중간 계산 범위는 헤더를 확인하세요. 특히 기존 `kq2d_body_apply_friction`은 계수를 부호 있는 8비트 값으로 변환하므로 128~255가 음수가 됩니다. 이를 일반적인 부호 없는 Q8 감쇠 계수로 사용하면 안 됩니다. 한 스텝을 실행하는 예제는 `gb_circle.c`입니다.

`wire3d_dmg`는 게임보이용 흑백 와이어프레임 렌더링 라이브러리입니다. 128×96 화면에는 `wire3d_dmg_96.c`, 128×120 화면에는 `wire3d_dmg.c`를 빌드하고 `Wire3DDMG_*` 함수를 사용하세요. 기존 `wire3d`와 `dmg3d` 파일은 각각의 설정을 선택하는 호환용 진입점으로 남아 있습니다. 진입점은 하나만 빌드해야 합니다. 컬러 전용 `wire3d_cgb`의 이름은 그대로 유지됩니다. 각 렌더러가 사용하는 RAM, VRAM, 화면 영역을 명확히 확보하세요. 두 흑백 렌더러는 깊이 범위를 가로지르는 선분을 잘라 그리지 않고 생략합니다. 장면의 가려짐도 면의 경계 사각형과 선 위의 다섯 점으로 근사하므로 픽셀별 깊이 검사가 아닙니다. CGB 경로는 배속과 DMA를 사용하며 `--cgb=cgb_only`가 필요합니다.

`Wire3DDMG_BeginFrame` (`WIRE3D_DMG_HEIGHT=96`)은 그리기 버퍼를 지웁니다. 반면 `Wire3DDMG_BeginFrame` (`WIRE3D_DMG_HEIGHT=120`)은 가려짐 검사 상태만 초기화하며, DMG3D의 버퍼 데이터는 VRAM에 전송할 때 지워집니다. 변경된 타일만 전송하는 모드에서는 이전 프레임의 타일도 처리하여 옛 픽셀을 없앱니다. 보조 전송은 주 버퍼의 일부를 공유하므로 독립된 버퍼가 아닙니다. 사용하는 렌더러에 맞게 프레임 처리 순서를 구성하세요.

CGB의 선 색상에는 1, 2, 3을 사용합니다. 일반 128 × 96 모드에서는 색상 비트를 겹쳐 그리므로 색상 1과 2가 겹치면 색상 3이 됩니다. 색상 0으로 선을 지울 수는 없습니다. 프레임을 지우거나 전용 지우기 함수를 사용하세요. 일반 `Wire3DCGB_DrawLine2D`와 모델 그리기 함수는 부분 전송 범위를 기록하지 않습니다. 선을 그리면서 범위도 기록하려면 `Wire3DCGB_DrawLineClipped2D`를 사용하고, 다음 부분 전송에 화면 전체를 포함하려면 `Wire3DCGB_InvalidateFrameHistory`를 호출하세요.

160 × 144 모드에서는 프레임당 최대 127개의 타일을 할당합니다. 고속 선 그리기 경로에서 타일 할당에 실패하거나 화면 밖 좌표를 만나면 `Wire3DCGB_GetFullScreenOverflow()`가 0이 아닌 값을 반환하며, 다음 프레임 초기화까지 픽셀 쓰기가 중단됩니다. 꼭짓점은 선택한 화면 영역 안에 두세요. 삼각형 마스크의 오른쪽 여유 폭은 128 × 96 모드에서 X=127, 전체 화면 모드에서 X=159까지만 확장됩니다. 특히 전체 화면과 FastMap을 사용할 때는 각 API에 명시된 WRAM 뱅크 설정을 지켜야 합니다.

## 10. 장면, 오브젝트 풀, 탄막
`scene`은 타이틀·플레이·일시정지 같은 상태, `entity`는 고정 용량 오브젝트 풀, `chain`은 뱀·기차·밧줄용 좌표 이력을 관리합니다. `entity_get`의 포인터를 사용하기 전에 0xFF 같은 할당 실패값을 확인하세요.

`danmaku`는 고정소수점 탄환 풀, 방향·부채꼴 발사, 충돌, 스침을 제공합니다. CGB 배경 합성 경로는 일반 OBJ 수 제한을 피하지만 프레임 처리 시간과 배경 전송 대역폭은 여전히 제한됩니다. 탄환 수만 늘리기보다 프레임 처리 시간을 측정하세요.

## 11. RPG, 어드벤처, 전략, 저장
`rpg.h`는 난수, 플래그, 퀘스트, 압축, 문자, 메뉴, 스크립트, 맵, 저장, 길 찾기 선언을 모읍니다. 구현은 `rng.c`, `flags.c`, `rle.c`, `text.c` 등에 나뉘어 있습니다. 사전에서 필요한 구현 파일을 선택하세요.

`rng_seed`를 고정하면 시험에 쓸 난수열을 재현할 수 있습니다. 범위 함수가 상한을 포함하는지도 확인하세요. `flag_get`, `flag_set`은 비트 집합을 다룹니다. `save.c`는 MBC5 방식 SRAM 접근을 사용하므로 ROM 헤더의 RAM 용량과 실제 저장 영역을 맞춰야 합니다.

`slg.h`의 보드, 수 목록, 되돌리기와 `slg_path.c`의 길 찾기는 게임 고유의 규칙·평가와 분리하세요. 너비, 높이, 작업 배열은 개별 인수 조건뿐 아니라 라이브러리 한도에도 맞아야 합니다.

## 12. 통신
`link.c`는 시리얼 바이트 전송, `link_packet.c`는 선택적인 패킷 계층입니다. `link_hwregs_gb.c`를 먼저 링크하세요. 폴링과 인터럽트 모드는 필요한 호출이 다르며, 인터럽트 모드는 게임 측에서 0x0058 벡터를 연결해야 합니다.

논리 `Link4_*`와 실제 Nintendo DMG-07용 `LinkDmg07_*`는 별개 체계입니다. DMG-07은 외부 클록을 사용하므로 `LinkDmg07_Poll`을 자주, `LinkDmg07_TickFrame`을 프레임마다 한 번 호출하세요. 프레임당 한 번만 폴링하면 타이밍 요구를 충족하지 못할 수 있습니다. KOKURA의 pair/dmg07 작업에서 연결, 시작, 연결 해제, 재연결을 각각 시험하세요.

## 13. 뱅크, 리소스, 디버깅
`BankPtr`는 뱅크 번호와 포인터를 결합합니다. `far_data_read`는 다른 뱅크의 리소스를 RAM으로 읽습니다. asset 모듈은 ID와 기술자를 연결하지만 수명, 뱅크, 크기는 게임이 관리해야 합니다.

`debug_trace_u8`, `debug_trace_u16`은 값을 RAM에 기록하고 `debug_assert_fail`은 진단 코드를 남깁니다. PC 콘솔로 출력하는 `printf`가 아닙니다. 에뮬레이터의 메모리 관찰로 기록을 확인하세요. `gb_debug.c`는 HP=42를 기록합니다.

`vram_get_queue_capacity()`는 전체 명령 슬롯 수(기본값 32), `vram_get_queue_free()`는 빈 슬롯 수, `vram_get_queue_used()`는 사용 중인 슬롯 수를 반환합니다. 전송량과 관계없이 예약한 작업 하나가 슬롯 하나를 차지합니다. 이 값은 전송 큐의 용량이며, 실제 VRAM의 빈 공간을 뜻하지 않습니다.
