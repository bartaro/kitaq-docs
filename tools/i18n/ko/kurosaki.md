## 빌드된 Windows CLI
저장소 루트에 `kurosaki.exe`가 들어 있습니다. ZIP을 내려받아 실행 파일과 라이선스 문서를 함께 보관하세요. Windows x64용 CLI는 실행 시 Rust, Python, .NET 설치가 필요하지 않습니다. 아래 절차는 소스에서 다시 빌드할 때 사용합니다. 독자적으로 작성한 프로젝트 코드는 DAISUKE OBA가 MIT로 제공합니다. 의존 라이브러리의 조건은 `BINARY_NOTICES.md`와 `licenses/`에 유지합니다.

## 1. KUROSAKI의 역할
KUROSAKI는 KITAQFC의 정보를 읽어 활용하는 NES·패미컴·FDS 관찰용 에뮬레이터입니다. CLI에서 ROM 검사, 실행, 녹음, 진단, 상태 저장, 입력 재생, 역어셈블, 함수 후보 디컴파일을 수행합니다. 매퍼별 구현 범위가 다르므로 ROM과 지원 정보를 먼저 확인하세요.

## 3. 매퍼와 보드 확인
`mapper-list`는 등록된 매퍼 종류, `mapper-info`는 특정 매퍼의 설명, `audit-board`는 보드 제약 검사를 제공합니다. 매퍼 번호는 ROM 헤더와 실제 배선에 관한 가정을 연결합니다. 이름만으로 용량, CHR-RAM, 고정 뱅크 동작이 확인되는 것은 아닙니다.

{{CODE:2}}

`--allow-unimplemented`를 사용하면 미지원 요소를 만난 뒤에도 관찰을 계속할 수 있습니다. 이 옵션을 사용한 실행은 해당 요소가 지원된다는 증거가 아닙니다.

## 4. 컨트롤러 입력
`run --pad1`, `--pad2`는 NES 원시 버튼 마스크를 사용합니다. A=1, B=2, SELECT=4, START=8, UP=16, DOWN=32, LEFT=64, RIGHT=128입니다. 동시에 누를 버튼의 값을 더해 지정하세요.

{{CODE:3}}

이 예는 A를 120프레임 동안 누릅니다. 타이틀 → 시작 → 확인처럼 순서가 있는 조작에는 리플레이를 사용하세요. CLI의 `replay-record` 예는 대화형 입력 없이 기준 실행을 기록하며, 사람이 GUI를 조작하는 모습을 녹화하는 것과 다릅니다.

## 5. 스냅샷과 리플레이
{{CODE:4}}

재개 가능한 상태는 버전 2 스냅샷을 사용합니다. 상태와 ROM의 SHA-256을 맞춰 보관하세요. `snapshot-resume`은 저장 지점에서 실행을 이어 갑니다. `snapshot-rebase`는 명시한 호환성 계약에 따라 다른 ROM으로 상태를 옮깁니다. 코드나 RAM 배치를 바꾼 뒤 예전 상태를 무조건 재사용하면 안 됩니다. 보통은 시작부터 같은 조작을 다시 수행하는 편이 적절합니다.

## 6. 트레이스, 진단, 프로파일
{{CODE:5}}

트레이스는 시간에 따른 사건, 진단은 규칙에 해당하는 관찰, 프로파일은 실행이 집중된 위치를 보여 줍니다. 긴 전체 기록보다 이상 현상 전후 몇 프레임을 살펴보는 편이 이해하기 쉽습니다.

`--kitaqfc-debug`에는 해당 빌드와 일치하는 디버그 JSON을 전달하세요. 소스 줄 정보가 없는 관찰을 완전한 소스 수준 트레이스로 해석하면 안 됩니다.

## 7. 화면과 소리 저장
{{CODE:6}}

레지스터 변화, PCM 생성, 올바르게 들리는 소리는 서로 다른 검사입니다. 기본 음원과 확장 음원을 시험할 때는 매퍼도 기록하세요. PNG 한 장만으로 움직임이나 입력 동작을 확인할 수 없으므로 전후 상태와 입력도 함께 남기세요.

## 8. 역어셈블과 디컴파일
{{CODE:7}}

`disasm`은 명령열을, `decompile`은 함수 경계 후보, CFG, 참조, 의사 코드를 출력합니다. 전환 가능한 뱅크에서는 CPU 주소만으로 ROM의 실제 위치를 특정할 수 없습니다. 필요하면 `--snapshot`으로 매퍼 상태를 제공하고, 실행 트레이스나 주석을 근거로 대조하세요. 원본 소스의 완전한 복원은 아닙니다.

## 9. SARAKURA 연동
{{CODE:8}}

KUROSAKI의 `--emit-diagnostics`에도 KOKURA와 마찬가지로 **JSONL 파일 경로**를 전달합니다. CPU 트레이스와 진단 이벤트 파일을 구분해 보관하세요.

## 10. 공개 범위
KUROSAKI-GUI는 아직 공개하지 않습니다. 현재 설명서는 CLI와 연동 API를 다룹니다.

## 11. FDS와 세이브 RAM
`fds-inspect`는 디스크 구조를 검사하고 `export-assets`는 리소스를 내보냅니다. FDS는 시작, BIOS, 디스크 접근 조건이 NES 카트리지와 다르므로 별도로 시험하세요. 배터리 저장용 `.sav`와 `.kss.json` 스냅샷은 목적이 다릅니다. 구현이 지원하는 저장 구성을 사용해야 합니다.

{{CODE:9}}

`battery-export`는 서로 일치하는 ROM과 스냅샷에서 원시 세이브 RAM을 추출합니다. `battery-run`은 그 RAM을 읽고 전원 투입 상태에서 시작합니다. 중단된 CPU·PPU 실행 상태를 복구하는 기능은 아닙니다. 출력은 `--save-out`으로 지정하세요. 이 기능은 세이브 RAM을 갖춘 지원 ROM에 필요하며, 모든 학습용 ROM에 적용되는 것은 아닙니다.
