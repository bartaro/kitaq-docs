## 1. KITAQFC와 GB 컴파일러의 관계
KITAQFC는 KITAQGB의 프런트엔드를 사용하여 NES·패미컴의 6502 계열 CPU용 코드를 생성합니다. GB ROM을 NES ROM으로 변환하는 도구는 아닙니다. 대상 기종의 화면, 음향, 메모리, 매퍼에 맞춰 프로그램을 작성하세요.

KITAQFC는 구조체 복사, 일반 함수 호출, for, while, do-while을 지원합니다. do-while은 본문을 적어도 한 번 실행한 뒤 조건을 검사합니다. continue는 마지막 조건 검사로 이동하고, break는 반복문을 빠져나갑니다. switch는 선택값에 맞는 0..255 범위의 case 상수를 찾고, 일치하는 case가 없으면 default 본문을 실행합니다. 선택식은 한 번만 평가합니다. break는 가장 안쪽의 반복문이나 switch를 빠져나가며, switch 안의 continue는 바깥 반복문의 다음 반복으로 진행합니다.

## 4. 언어의 기본
GB편의 문장과 식을 공통 출발점으로 삼을 수 있습니다. FC에서는 `unsigned char`, `unsigned short`를 사용할 수 있고, `core.h`가 `u8`, `u16`, `s8`, `s16`을 정의합니다. `fc.h`는 여러 헤더를 모아 둔 통합 헤더입니다. 이쪽에서는 인수 없는 시작 함수를 `void main(void)`로 작성할 수 있습니다.

### 식의 결과와 평가 순서

비교 연산자 `==`, `!=`, `<`, `<=`, `>`, `>=`와 논리 연산자 `!`, `&&`, `||`는 거짓이면 0, 참이면 1을 반환합니다. 결과를 `u16`에 저장하거나 인수·반환값으로 전달하거나 산술 연산에 사용할 수 있습니다. 예를 들어 `score = 500 + (lives != 0);`은 잔기가 있으면 501, 없으면 500을 만듭니다.

`&&`는 왼쪽 피연산자가 0이면 오른쪽 피연산자를 평가하지 않습니다. `||`는 왼쪽이 0이 아니면 오른쪽을 평가하지 않습니다. `pointer != 0 && pointer->active != 0`에서는 포인터가 NULL이면 멤버에 접근하지 않습니다. 16비트 값은 두 바이트를 모두 사용하여 참·거짓을 판단하므로 256도 참입니다. 비트 연산자 `&`와 `|`는 단락 평가를 하지 않습니다.

`++value`는 갱신한 값을 반환하고, `value++`는 갱신 전 값을 반환합니다. 배열 원소, 역참조한 포인터, 구조체 멤버에도 사용할 수 있습니다. `buffer[index()]++`는 `index()`를 한 번만 호출합니다. `u16 *p`에서 `p++`는 다음 원소를 가리키도록 2바이트 이동하고, `(*p)++`는 가리키는 값을 증가시킵니다.

`sizeof(array)`는 배열 전체의 바이트 크기를 반환하고, `sizeof(pointer)`는 2입니다. `u16 values[9];`를 선언하면 `sizeof(values)`는 18입니다. ROM 배열, 지역 배열, 배열 멤버에도 적용됩니다. `sizeof(function())`은 함수를 호출하지 않고 반환형을 조사합니다.

함수의 선언과 정의는 매개변수의 자료형과 순서가 일치해야 합니다. 매개변수 이름은 달라도 되며, 함수 본문은 정의에 쓴 이름을 사용합니다. 예를 들어 `u8 next(u8 input);`의 정의를 `u8 next(u8 value) { return (u8)(value + 1); }`로 작성할 수 있습니다. 매개변수와 지역 변수는 같은 이름의 전역 변수를 가립니다.

`?:`로 배열이나 문자열을 선택하면 선택한 원소형을 가리키는 포인터가 됩니다. `show(ready ? "READY" : "WAIT");`처럼 곧바로 인수로 전달할 수 있습니다. `u16` 배열 `a`, `b`에서 `(ready ? a : b) + 1`은 선택한 배열의 두 번째 원소를 가리키도록 2바이트 이동합니다. 배열을 복사하는 것은 아닙니다.

`condition ? yes : no`는 조건을 평가한 뒤 선택된 쪽만 평가합니다. 조건과 양쪽 식에는 가변 비트 수만큼의 시프트가 들어갈 수 있습니다. 예를 들어 `on = (pattern & (0x80 >> bit)) != 0 ? 4 : 2;`는 지정한 비트에 따라 4 또는 2를 선택합니다. `&&`나 `||`가 건너뛴 오른쪽 피연산자 안의 함수도 호출하지 않습니다. `for` 안의 `continue`는 갱신 식을 한 번 실행한 뒤 조건을 다시 평가합니다. `while`과 `do ... while`에서는 조건 평가로 이동합니다.

## 5. 반복문과 상태별 처리

이 코드 조각은 본문을 최소 한 번 실행하는 반복문과 현재 상태에 맞는 처리 함수를 선택하는 분기를 보여 줍니다. update, condition, state와 상태별 처리 함수는 프로그램에서 정의하세요. 완전한 반복문 예제는 fc_control.c, 장면 관리 ROM 전체 예제는 라이브러리의 프레임·장면 예제를 참고하세요.

장면·엔티티·시스템 콜백은 선언에서 요구하는 인수형과 반환형에 맞춰 등록하세요. 라이브러리는 해당 갱신·그리기·프레임 대기 작업에서 등록된 처리 함수를 호출합니다. 각 API의 ROM 뱅크 및 매핑 조건을 지키세요. 재귀 호출이나 가변 인수 함수가 데스크톱과 동일하게 지원된다고 가정하지 마세요.

## 6. 메모리와 PPU
NES의 CPU 내부 RAM은 0x0000~0x07FF입니다. 0x0800 위의 미러 영역은 추가 RAM이 아닙니다. 6502 스택은 페이지 1을 사용하며, OAM 섀도와 큐도 별도의 영역을 예약합니다. `--nes-local-ram=START:LENGTH`, `--nes-temp-ram=START:LENGTH`는 맵 확인이 필요한 고급 설정입니다.

PPU는 CPU와 별도의 주소 공간을 사용합니다. CHR은 무늬, 네임테이블은 타일 배치, 속성 테이블은 팔레트 그룹, 팔레트는 색 코드를 담습니다. 배경 속성은 보통 16×16픽셀 영역에 적용되므로 GB의 타일 속성과 다르게 동작합니다.

## 7. NMI와 VRAM 큐
NMI는 화면 프레임 경계와 관련된 인터럽트입니다. 렌더링 중 대량으로 PPU에 직접 쓰면 화면이 깨질 수 있습니다. 초기화는 화면을 끈 상태에서 직접 수행하고, 평소 갱신에는 `__vramq_put`, `__vramq_copy`, `__vramq_fill`과 커밋을 사용하세요.

큐 용량과 소스 데이터의 유효 기간을 확인하세요. 기본 NMI 처리기는 큐를 처리합니다. 사용자 정의 `__nes_nmi`를 작성한다면 필요한 큐 실행, OAM 처리, 레지스터 보존을 유지해야 합니다.

## 8. 매퍼와 ROM 구성
| 선택값 | 입문 시의 용도 |
| --- | --- |
| nrom | 고정 ROM을 쓰는 작은 예제 |
| uxrom / cnrom / axrom | 간단한 PRG·CHR 전환 |
| mmc1 / mmc3 / mmc5 | 큰 프로그램과 매퍼 고유 기능 |
| vrc6 / vrc7 / fme7 | 뱅크 전환과 해당 확장 기능 |
| fds | 디스크 이미지 출력 |

이 표는 컴파일러의 선택값 목록이며, 실기나 에뮬레이터의 구현 완성도 표가 아닙니다. `--board=surom512`는 특정 MMC1 보드 구성을 선택합니다. 파일 뒤를 채워 512KiB로 만드는 것만으로 그 구성이 성립하지는 않습니다. KUROSAKI의 보드 검사도 함께 이용하세요.

{{CODE:6}}

`--battery` / `--no-battery`, CHR 용량, PRG 배치, 뱅크 간 호출이 보드 요구 사항과 맞는지 확인하세요. 매퍼나 미러링을 바꾼 뒤에는 ROM 생성뿐 아니라 시작 동작, 스크롤, 데이터 전환도 시험해야 합니다.

ROM 배열에 대한 일반적인 인덱스 읽기와 C 포인터 참조는, `#pragma fixed_bank`로 배치를 명시하지 않은 한 해당 배열을 공통 뱅크 0에 둡니다. 따라서 호출 코드가 전환 가능한 뱅크에서 실행되어도 데이터에 접근할 수 있습니다. 명시적인 far 접근에는 같은 호출 안에서 배열 이름 자체와 그 이름에 대한 `__bankof`를 함께 전달하세요. 예를 들면 `__farpeek8(__bankof(table), table)`입니다. 뱅크 번호 조회만으로는 공통 뱅크 배치를 요청하지 않습니다. 명시적으로 고정한 뱅크의 데이터와 어셈블리 내부 참조는 직접 올바른 매핑을 유지해야 합니다. 이 규칙은 구문에 따른 배치 검사이며 포인터 흐름 분석이 아닙니다. 공통 뱅크의 용량 제한도 적용됩니다.

## 9. FDS, 확장 음원, 주변기기
FDS 개발에는 디스크 파일 배치, 시작 절차, 오버레이, 저장이 관계됩니다. `fds_manifest_sample.json`과 FDS 헤더를 참고하세요. 필요한 BIOS는 자신의 실행 환경에 별도로 준비해야 하며 공개 배포본에는 포함되지 않습니다.

VRC6·VRC7 음원 함수를 호출한다고 ROM의 매퍼 설정이 바뀌지는 않습니다. 사용하는 확장 음원에 맞는 매퍼를 선택하세요. 주변기기는 입력값, 연결 상태, 일반 컨트롤러 경로에 미치는 영향을 각각 확인해야 합니다.

## 10. 진단과 빌드 결과
KQ 진단과 `symfind`, `src2asm`, `romdiff` 같은 개발 명령은 GB판과 비슷합니다. 다만 GB에서 상속한 도움말 항목 중에는 NES에 구현되지 않은 기능도 있을 수 있습니다. FC API 사전은 FC 소스와 헤더에서 별도로 수집했습니다.

직접 PPU 조작에 대한 KQ2421 같은 경고는 화면을 끈 초기화에서도 나올 수 있습니다. 경고를 없애려고 안전한 초기화 순서를 깨뜨리지 마세요. 렌더링 시점과 실행 로그를 확인해야 합니다. ‘오류 없음’과 ‘경고 없음’은 서로 다른 결과입니다.

## 소스 위치
컴파일러 소스와 프로젝트 파일은 저장소 안의 같은 이름을 가진 하위 폴더에 있습니다. 실행 파일은 저장소 루트에, 라이브러리는 `lib/`에 있습니다. 프로젝트 경로와 빌드 요구 사항은 [폴더 구성 안내](../GITHUB_SETUP.md)를 참고하세요.
