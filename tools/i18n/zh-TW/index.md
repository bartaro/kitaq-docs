## 從這裡開始
KITAQGB 起初是 Zachtronics 相關 NES C 編譯器 **NORCAL 的分支專案**。在這個基礎上，專案針對 Game Boy 與 Game Boy Color 的處理器、記憶體、影像、音訊及 ROM 分頁機制加以擴充，形成一套 C 語言開發工具。我們保留原作者 Keith Holman 的著作權聲明，也感謝原專案的貢獻。

NORCAL 的開發與 NES 版 HACK*MATCH 有關。背景可參閱原作者的 [NORCAL 介紹](https://keithholman.net/nes-compiler.html)與 [NES 版 HACK*MATCH 介紹](https://trashworldnews.com/hack-match/)。

## 如何使用這套手冊
這套手冊採用早期電腦手冊的方式：先輸入一個小程式，完成編譯並看到執行結果，再逐步認識機器的運作。剛開始不必記住所有術語。

1. GB 開發從第 1 卷的第一個程式開始；FC 開發則從第 4 卷開始。
2. 透過第 2 卷或第 5 卷加入輸入、圖像和聲音。
3. 使用 KOKURA 或 KUROSAKI 觀察執行，再由 SARAKURA 整理診斷結果。
4. 已知函式名稱時，可直接使用卷內搜尋或 API 辭典。

語言語法、編譯器內建函式、函式庫函式和命令列操作是不同類型的參考項目。編譯器分卷另附 CPU 指令索引。GB 與 FC 的函式即使同名，參數和行為也不一定相同。

## 七卷各自負責什麼
| 分卷 | 輸入 | 輸出或用途 |
| --- | --- | --- |
| KITAQGB | C 原始碼與素材 | GB/CGB ROM、配置檔及建置資訊 |
| KITAQGB 函式庫 | 遊戲程式中的呼叫 | 圖像、音訊、輸入、通訊與遊戲輔助功能 |
| KOKURA | GB/CGB ROM | 執行、畫面、音訊、狀態與觀察紀錄 |
| KITAQFC | C 原始碼與 CHR 素材 | NES/FDS 輸出及建置資訊 |
| KITAQFC 函式庫 | 遊戲程式中的呼叫 | NES 圖像、音訊與周邊裝置功能 |
| KUROSAKI | NES/FDS 映像檔 | 執行、記錄與分析 |
| SARAKURA | 建置資訊與診斷事件 | 報告、修復計畫及複測計畫 |

## 範例使用的字形
26 個大寫字母、10 個數字、26 個小寫字母及 30 個符號皆來自作者提供的 [ascii.c](samples/assets/ascii.c)。沒有另外設計或補入字形，原有的 92 個字形都保持不變。請參閱[轉換對照表](verification/font_conversion.json)與[圖塊總覽](verification/font_source_atlas.png)。空格使用空白圖塊。原檔未提供反斜線和直線符號，這兩者會顯示為空白。`gb_font.c` 與 `fc_font.c` 可顯示所有已提供的字形。

## 版本與驗證範圍
本版以 **2026 年 9 月 14 日的本機原始碼快照**為準。「最新」指的是這份快照，不代表會自動追蹤日後 GitHub 的變更。參考清單記錄了原始碼和執行檔的識別指紋。舊 README 中的支援或驗證說明，不會直接被視為目前版本的保證。

建置成功表示已產生 ROM；執行檢查表示模擬器前進了指定的影格數。像素比對、輸入行為和音訊檢查分別記錄。這些檢查並不保證所有周邊裝置或實體主機的相容性，日誌中的警告也予以保留。

目前公開的原始碼不包含 KOKURA-GUI、KUROSAKI-GUI 與 PLITA。請使用已公開的核心、CLI 和整合 API。

## 準備工作目錄
範例命令以 **Windows PowerShell** 為準。C 檔案請儲存為 UTF-8 文字。「目前目錄」就是執行命令的位置。含空格的路徑需加引號；必要時使用 `& "路徑"` 呼叫執行檔。依照 [GitHub 目錄配置說明](../GITHUB_SETUP.md)，將各儲存庫複製到同一個上層目錄下，跨專案命令從該目錄執行。

## 本版採用的編譯器修正
建置範例時發現 KITAQGB 內部區域標籤撞名，以及 KITAQFC 在函式呼叫前後保留中間值和傳回值的問題。紀錄中的檢查使用修正後的編譯器，包含 GB 物件池及 FC 函式、結構範例。但這並不表示支援所有 C 語言結構。詳情請查看各範例的[驗證紀錄](verification.html)。
