## 1. 認識 KITAQGB
KITAQGB 是由 Zachtronics 的 NORCAL 發展而來的 GB/CGB C 語言編譯器。

{{ORIGIN}}

它讀取 C 檔案，產生 CPU 指令，再封裝成主機可讀取的 ROM。語言、函式庫和呼叫慣例與桌面 C 編譯器並不完全相同。

GB 使用 8 位元 CPU，記憶體有限。畫面主要由 8×8 像素圖塊構成；精靈則是能獨立定位的小圖像。文字也需要圖塊，不能假設系統內建通用文字顯示。本例採用作者的 `ascii.c`，依 GB 的 ASCII 順序重排而不更動字形位元；FC 版則轉成 NES CHR 配置。

## 4. 基本語法與型別
敘述以 `;` 結尾，多個敘述用 `{ }` 分組。`//` 開始單行註解，`/* ... */` 表示區塊註解，名稱區分大小寫。入口請寫成 `void main()`。**本 GB 版本的 `void main(void)` 會造成語法錯誤**，不要直接照搬 FC 的入口宣告。

| 型別 | 意義與範圍 |
| --- | --- |
| `u8` | 無號 8 位元整數，0～255 |
| `s8` | 有號 8 位元整數，-128～127 |
| `u16` | 無號 16 位元整數，0～65535 |
| `s16` | 有號 16 位元整數，-32768～32767 |
| `void` | 無傳回值 |
| `T*` | 指向 T 型別資料的指標 |

入門時建議使用這些短型別名稱。不要假設 `int`、`long`、`float`、`double` 或標準標頭與桌面環境相同。本版 `char` 是無號 8 位元資料；需要負數時請明確使用 `s8` 或 `s16`。

{{CODE:3}}

`(u16)` 是型別轉換。小型別已經溢位的值，再指定給大變數也無法找回遺失的位元；應在計算前擴大運算元的型別。小數單位的移動可使用定點數函式庫。

## 5. 運算式與運算子
| 類別 | 運算子 | 範例或意義 |
| --- | --- | --- |
| 算術 | `+ - * / %` | `n / 10` 求整數商，`n % 10` 求餘數 |
| 比較 | `== != < <= > >=` | `lives == 0` 判斷相等 |
| 邏輯 | `! &&` / `||` | 非、兩條件都成立、任一條件成立 |
| 位元運算 | `&` / `|` / `^ ~ << >>` | 按鈕遮罩與其他位元集合 |
| 指定 | `= += -=` 等 | `x += 1` 更新數值 |
| 遞增遞減 | `++ --` | `i++` 增加 1 |
| 條件選擇 | `condition ? A : B` | 依條件選擇數值 |
| 指標 | `&variable` / `*p` | 取得位址或存取指向的資料 |

請區分 `=` 與 `==`。複雜運算式用括號表明意圖，不要把太多函式呼叫和副作用塞進同一個敘述。避免除以零及陣列越界。`sizeof` 傳回位元組數，`offsetof` 傳回結構成員的位移。

## 6. 分支與迴圈
{{CODE:4}}

`break` 離開迴圈或 switch，`continue` 進入下一輪，`return` 結束函式。若要從一個 switch case 繼續執行下一個，請明寫 `fallthrough;`；隱含的接續執行會觸發診斷。完整程式請看 `gb_control.c`。

## 7. 函式、陣列與結構
{{CODE:5}}

陣列索引從 0 開始，四個元素的合法索引為 0～3。`player.x` 存取成員，`pointer->x` 透過指標存取成員。剖析器接受結構、聯合與列舉，但配置取決於型別及 `__packed` / `__aligned` 屬性。與硬體或二進位格式交換資料前，請檢查 `sizeof`。

預設 Legacy ABI 將引數與區域儲存放在固定位置。不要假設能像桌面環境一樣遞迴呼叫或從中斷重新進入函式。`__stackcall` 和 `--abi=stack` 是進階呼叫慣例設定；混用時應閱讀 ABI 報告並驗證執行。

## 8. 多檔案與前置處理器
型別、常數和宣告放在標頭檔，函式本體放在 `.c` 檔。使用 `#pragma once` 或標頭保護巨集避免重複引入。條件式編譯支援 `#define`、`#undef`、`#if`、`#ifdef`、`#ifndef`、`#elif`、`#else`、`#endif`。

{{CODE:6}}

`-I` 加入標頭搜尋目錄。引入標頭不等於連結實作，建置命令仍須列出所需 `.c` 檔。請按需選擇；不分用途加入全部函式庫來源，可能造成暫存器定義或中斷處理常式重複。

## 9. ROM、記憶體與分頁
ROM 儲存程式碼與常數，WRAM 儲存變數，VRAM 儲存圖像，OAM 儲存精靈描述。切換 bank 會改變 CPU 位址對應到的實際記憶體。單一 16 位元指標無法辨識另一個 bank 的資料。

{{CODE:7}}

`__prg_rom` 將資料放入 ROM；`__location(0xFF40)` 等屬性指定固定位址，`__wram` / `__hram` 指定記憶體區域。使用 `#pragma bank`、`#pragma fixed_bank` 時，請檢查配置檔，確保中斷用到的程式碼與資料始終可存取。

{{CODE:8}}

`--cgb=dmg` 宣告 DMG 軟體，`--cgb=cgb` 宣告雙模式軟體，`--cgb=cgb_only` 宣告 CGB 專用軟體。雙模式遊戲必須先辨識硬體，再使用 CGB 專用功能。ROM 標頭旗標不會代替你實作遊戲內的模式切換邏輯。

## 10. 安全更新圖像
VBlank 是顯示影格之間的空白期間。時機不對的 VRAM/OAM 寫入可能造成畫面損壞或更新遺失。初始素材應在關閉顯示時載入，平常更新則用安全內建函式或 VRAM 佇列。帶 `_unsafe`、`_fast` 的函式，需要呼叫端保證安全的傳輸時段。

OAM DMA 緩衝區須對齊 256 位元組邊界。GB 的 `__oam_dma` 接收來源位址，FC 的同名內建函式沒有引數，兩者不可混用。

## 11. 建置選項與輸出檔
`-o` 選擇輸出，`-O0` / `-O1` 選擇最佳化層級，`--profile=dev|release|test` 選擇設定組合。`--no-disasm` 關閉反組譯輸出；`--debug-out=...`、`--trace-out=...` 指定調查資料位置。依快速建置或詳細排查的需要選擇輸出量。

{{CODE:9}}

`.map` 記錄名稱與配置，`.funcsizes.txt` 記錄函式大小，`.dbg2.json` / `.source_map.txt` 對應執行位置與原始碼，`.build_report.json` 彙整建置結果。明確產生 `--emit-ai-metadata` JSON，能讓 SARAKURA 的輸入關係更清楚。

## 12. 從第一個錯誤讀起
先看首個錯誤的檔名、行號和 KQ 診斷編號；後續錯誤可能只是第一個語法問題引起的連鎖反應。未定義符號應檢查宣告、實作，以及是否納入建置。ROM 超出容量時，請查看素材大小、函式大小與 bank 配置。

## 13. 行內組合語言
