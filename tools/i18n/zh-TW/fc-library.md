## 1. 選擇需要的元件
`fc.h` 統整宣告，`core.h` 定義型別，`intrinsics.h` 宣告編譯器操作。一般 C 函式庫函式需要對應的 `.c` 實作；僅由標頭定義的巨集和內建函式，不一定需要同名來源檔。

不要將 `-I` 指向名稱相似的 GB 函式庫。例如 NES 的 `__oam_dma()` 沒有引數，但 GB 同名操作會接收指標。

## 2. Runtime 與 system
`runtime.c` 為 PPU 暫存器、OAM 影子緩衝區與 VRAM 佇列提供 C 輔助函式，也有 `__vramq_*` 等內建路徑。請先確認 NMI 實際使用的資料，不要混用名稱近似、實際獨立的佇列。

`system_init` 初始化影格狀態並開啟 NMI；`system_wait_vblank` 等待 NMI，再增加軟體影格計數。**FC 的 `system_set_vblank_callback` 只儲存回呼值，目前的等待函式不會執行它。** 不要假設與 GB 相同，將全部遊戲更新放進這個回呼。

## 3. PPU、圖塊、屬性與調色盤
`ppu_direct.h` 提供直接 PPU 操作，`vram_queue.h` 用於 NMI 更新，`tilemap` / `nametable_asset` 管理表格與素材，`attribute` 更新屬性，`palette` 管理調色盤。初始載入與每影格的工作應分開。

背景與精靈調色盤各占 16 位元組。值是 NES 色彩編號，不是 RGB 分量。屬性為一組圖塊選色，因此改變單一圖塊的配色也可能影響相鄰圖塊。

`ppu.h` 的部分宣告與 `ppu.c` 的實作名稱不一致。標為**僅有宣告**的項目，在收集範圍內未找到實作，入門範例不會直接呼叫。可執行課程使用已驗證的內建函式。只有宣告，不能證明功能已完成或能夠連結。

## 4. OAM、組合精靈與輪替顯示
NES 最多有 64 個精靈，通常每條掃描線最多顯示 8 個。同一行集中九個以上敵人或子彈時，無法同時全部顯示。組合精靈用多個 OBJ 拼成一張圖像；請檢查配置界線與結束標記格式。

`oam_fair.h` 和 `oam_fair_impl.h` 會保留優先順序，同時輪替候選的排列。例如優先顯示玩家或 HUD，讓較不重要的物件輪流出現。重排 OAM 不會改變硬體的掃描線限制。

## 5. 輸入、重複輸入與周邊
`input.c` 將 NES 原始按鈕值轉成 GB 風格的 `BTN_*` 遮罩。**NES 原始 A 是 0x01，函式庫 BTN_A 是 0x10。** 不要把 BTN_A 直接傳給 KUROSAKI 的 `--pad1`。

`pad` 讀取基本輸入，`input_repeat` 處理長按重複。`zapper`、`keyboard`、`rob`、`mic`、`midi` 提供底層裝置介面。未連接裝置時讀到 0，不代表操作已驗證成功；應檢查該裝置的連接條件。

## 6. 聲音
在 `nes_apu_init` 之後，可透過 `nes_sfx_square1`、`nes_sfx_square2`、`nes_sfx_triangle`、`nes_sfx_noise` 使用內建音源。period 引數是硬體計時週期，不是以赫茲表示的頻率。`fc_sound.c` 是最小脈衝音範例。

DMC 樣本有位址、長度、對齊及速率限制，傳入指標前應查看配置。DMC DMA 也可能干擾控制器讀取，請搭配安全讀取方式與 KUROSAKI 診斷。

VRC6 提供額外脈衝與鋸齒波通道，VRC7 提供 FM 暫存器，FDS 提供波表音源。請使用相符的 mapper 並記錄結果。這些 API 與 GB 的 `Audio_*` 驅動程式不同。

## 7. 場景、actor 與 entity
`actor`、`entity` 用固定陣列保存遊戲物件，`scene` 保存場景狀態。必須偵測容量耗盡，並停止使用已銷毀的 ID。部分 FC API 目前只註冊回呼、不會呼叫；入門程式宜由主迴圈明確分派各狀態的更新函式。

`chain` 儲存座標歷史，`collision` 判斷矩形等形狀的接觸。固定採用「移動、碰撞、繪製」順序，可避免碰撞結果落後一個影格。

## 8. 數學與物理
`fixed.h` 提供 Q8.8 運算，`math_fast` / `math_fixed` 提供數值操作，`math_lut` 提供查表計算。目前 `physics2d.h` 提供 **Q5.3 型別與常數**，不是積分函式或更新巨集的實作，也不是 GB 的 world/body 物理 API。

Q5.3 的小數單位是 1/8 像素。請分別保存整數座標、小數部分、速度和方向，在遊戲程式中處理加法與進位。`fc_subpixel.c` 將 2/8 像素累加八次，從像素 40 移到 42。不可將 Q8.8 的 256 原樣當成 Q5.3 的 1。

## 9. 素材、mapper 與 FDS
`bank`、`asset` 描述 PRG bank 和素材。`mapper.h` 的操作是否有效，取決於建置時選用的 mapper。捲動 IRQ 的設定、開啟、確認和關閉，應設計成完整流程。

FDS 功能分布在 `fds_file`、`fds_overlay`、`fds_save`、`fds_sound`。載入覆疊模組會替換既有位址的程式碼，必須考慮返回位址與資料生命週期，不能假設等同於一般卡匣的遠端呼叫。

## 10. 參考項目與範例
下方辭典依公開標頭整理，區分函式、函式型巨集與別名。完整標頭也包含結構和常數。僅宣告 API、只儲存的回呼和專用周邊介面，會與已驗證的一般操作分開標示。原始碼註解保留原文，方便精確對照實作。

`vram_get_queue_capacity()` 傳回命令緩衝區的總容量，也就是128位元組。`vram_get_queue_free()` 傳回剩餘位元組數，等於總容量減去 `vram_get_queue_used()`。這裡計算的是包含位址等管理資訊的命令大小，並非實際 VRAM 的可用空間。寫入單一圖塊需要4位元組，填入相同值需要5位元組，透過指標複製需要6位元組。commit 後 NMI 可能處理佇列內容，因此請在 commit 前檢查剩餘空間。
