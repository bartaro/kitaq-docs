从这里开始

KITAQGB 最初是 Zachtronics 相关 NES C 编译器 NORCAL 的一个分支。在此基础上，项目针对 Game Boy 和 Game Boy Color 的处理器、内存、图像、音频及 ROM 分页机制进行了扩展，形成了一套 C 语言开发工具。我们保留原作者 Keith Holman 的版权声明，并感谢原项目的贡献。

KITAQGB 的名称有双重含义。 Kernel-Informed Toolchain for AI-Quality Game Boy Development 表达了理解目标机器、同时支持程序员和生成式 AI 的开发工具这一目标。另一层是 KITAQ + GB：KITAQ 代表日本福冈县北九州市的昵称北九（キタキュー，Kitakyū），GB 代表 Game Boy。KITAQ 的读法是日语“キタキュー”；给英语使用者的发音提示为 kee-tah-KYOO，国际音标为 /ˌkiːtɑːˈkjuː/，最后的 Q 与英语字母 Q 同音。KITAQGB 读作 kee-tah-KYOO jee bee，其中 G、B 分别按字母读出。

NORCAL 的开发与 NES 版 HACK*MATCH 有关。背景资料可参阅原作者的 NORCAL 介绍和 NES 版 HACK*MATCH 介绍。

怎样使用这套手册

这套手册沿用早期计算机手册的思路：先输入一个小程序，完成编译并看到运行结果，再逐步理解机器的工作方式。初学时不必先记住所有术语。

  1. 开发 GB 程序，从第 1 卷的第一个程序开始；开发 FC 程序，从第 4 卷开始。
  2. 通过第 2 卷或第 5 卷加入输入、图像和声音。
  3. 用 KOKURA 或 KUROSAKI 观察运行过程，再用 SARAKURA 整理诊断结果。
  4. 已经知道函数名称时，可直接使用卷内搜索或 API 字典。

语言语法、编译器内建函数、库函数和命令行操作是不同类型的参考条目。编译器分卷还附有 CPU 指令索引。GB 与 FC 中同名的函数，其参数和行为未必相同。

示例使用的字形

26 个大写字母、10 个数字、26 个小写字母和 30 个符号均来自作者提供的 ascii.c。没有另外设计或补入字形，原有 92 个字形均保持不变。可查看转换对应表和图块总览。空格使用空白图块。原文件没有反斜杠和竖线，它们会显示为空白。gb_font.c 和 fc_font.c 可显示全部已提供字形。

版本与验证范围

本版以 2026 年 9 月 14 日的本地源码快照为基准。“最新”指的是这个快照，并不意味着会自动跟踪此后 GitHub 上的更新。参考清单记录了源码和可执行文件的指纹。旧 README 中的支持或验证说明，不会被直接当作当前版本的保证。

构建成功只表示生成了 ROM；运行检查表示模拟器前进了指定帧数。像素对照、输入行为和音频检查分别记录。本手册不保证所有外设或真实主机的兼容性，日志中的警告也予以保留。

当前公开源码不包含 KOKURA-GUI、KUROSAKI-GUI 和 PLITA。请使用已经公开的核心、CLI 和集成 API。

准备工作目录

示例命令使用 Windows PowerShell。C 文件请保存为 UTF-8 文本。“当前目录”就是执行命令的位置。包含空格的路径需要加引号；必要时用 & "路径" 调用可执行文件。按照 GitHub 目录布局说明，把各仓库克隆到同一个父目录下，跨项目命令从该父目录执行。

powershell
# リポジトリのルートで実行します。
New-Item -ItemType Directory -Force out | Out-Null
.\kitaqgb\kitaqgb.exe --help
.\kitaqfc\kitaqfc.exe --help

请把 game.c、game.gb 和 game.nes 换成自己的文件名。<ROM> 这类尖括号内容表示占位参数，输入时不要保留尖括号。命令通常以单行给出。Bash 的反斜杠续行方式不适用于 PowerShell。

本版采用的编译器修复

构建示例时发现了 KITAQGB 内部局部标签重名问题，以及 KITAQFC 在函数调用前后保留中间值和返回值的问题。记录中的检查使用了修正后的编译器，包括 GB 对象池和 FC 函数、结构体示例。这并不等于支持所有 C 语言结构。具体情况请查看各示例的验证记录。

阅读、打印与发布 HTML

打开下载目录中的 index.html 即可离线阅读。样式、搜索、示例和验证图片都使用本地文件，不依赖外部 CDN。请保持整个目录结构，不要只复制某一个 HTML 文件。打印按钮会使用隐藏侧栏的打印布局。

手册网站位于 kitaq-docs 仓库。GitHub 的仓库浏览界面通常显示 HTML 源码，GitHub Pages 才将其作为网页呈现。发布和源码布局请参阅仓库 README。各语言版共用同样的七卷、API 条目、示例程序和验证资料。源码摘录及实际工具输出保留原文，便于准确核对。
