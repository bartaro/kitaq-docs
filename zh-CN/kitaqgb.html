1. 认识 KITAQGB

KITAQGB 是从 Zachtronics 的 NORCAL 发展而来的 GB/CGB C 语言编译器。

NORCAL的名称源于北加利福尼亚（Northern California）。 受这种以地域命名的思路启发，KITAQGB的作者DAISUKE OBA选择了自己出生并长大的城市——北九州市，作为KITAQGB名称的来源。

KITAQGB 的名称有双重含义。 Kernel-Informed Toolchain for AI-Quality Game Boy Development 表达了理解目标机器、同时支持程序员和生成式 AI 的开发工具这一目标。另一层是 KITAQ + GB：KITAQ 代表日本福冈县北九州市的昵称北九（キタキュー，Kitakyū），GB 代表 Game Boy。KITAQ 的读法是日语“キタキュー”；给英语使用者的发音提示为 kee-tah-KYOO，国际音标为 /ˌkiːtɑːˈkjuː/，最后的 Q 与英语字母 Q 同音。KITAQGB 读作 kee-tah-KYOO jee bee，其中 G、B 分别按字母读出。

它读取 C 文件，生成 CPU 指令，再封装成主机可读取的 ROM。它的语言、库和调用约定与桌面 C 编译器并不完全相同。

GB 使用 8 位 CPU，内存有限。画面主要由 8×8 像素的图块组成；精灵是可独立定位的小图像。文字同样需要图块，不能假定系统自带通用文字显示。本例采用作者的 ascii.c，按 GB 的 ASCII 顺序重新排列，但不改变字形位图；FC 版则转换为 NES CHR 布局。

2. 环境准备与编译器构建

安装支持 .NET Framework 4.8 目标的 Visual Studio/MSBuild 环境，并使用能够运行 MSBuild.exe 的 Developer PowerShell。

powershell
MSBuild.exe .\kitaqgb\kitaqgb\kitaqgb.csproj /t:Build /p:Configuration=Release
.\kitaqgb\bin\Release\kitaqgb.exe --help

请将可执行文件与配套配置文件放在同一目录，并在构建命令中明确指定编译器路径。构建项目时，可执行文件会复制到 kitaqgb 仓库根目录。

3. 第一个程序

samples/gb_hello.c 使用 gb_common.h 中的画面和文字辅助函数。请保留配套头文件与字体文件。#include 用于读入其他文件的声明或定义。

c
#include "gb_common.h"
void main() {
    m_init();
    m_text(2, 5, "HELLO WORLD");
    m_number(42);
    while (1) { m_wait(); }
}
powershell
.\kitaqgb\kitaqgb.exe .\kitaq-docs\samples\gb_hello.c -I .\kitaq-docs\samples -o .\out\hello.gb --profile=dev --rst-disable --stack-bank=fixed
.\kokura\kokura-cli.exe .\out\hello.gb --run-frames 120 --png .\out\hello.png --dump-report .\out\hello.json

预期画面显示 HELLO WORLD 和 042。以 m_ 开头的名称是公共示例头文件中定义的教学辅助函数，不是 KITAQGB 标准命令。编译器内建操作包括 __wait_vblank、__vram_copy 等。

4. 基本语法与类型

语句以 ; 结尾，多条语句用 { } 分组。// 开始行注释，/* ... */ 表示块注释，名称区分大小写。入口请写成 void main()。本 GB 版本中的 void main(void) 会产生语法错误，不要原样照搬 FC 的入口声明。

类型含义与范围
u8无符号 8 位整数，0～255
s8有符号 8 位整数，-128～127
u16无符号 16 位整数，0～65535
s16有符号 16 位整数，-32768～32767
void无返回值
T*指向 T 类型数据的指针

入门时建议使用这些短类型名。不要假定 int、long、float、double 和标准头文件与桌面环境相同。本版 char 是无符号 8 位数据；需要负数时请明确使用 s8 或 s16。

c
u8 lives = 3;
u16 score;
score = (u16)200 + 100;

(u16) 是强制类型转换。小类型已经溢出的值，即使再赋给大变量，也无法找回丢失的位；应在计算前扩大操作数的类型。小数单位的移动可使用定点数库。

类别运算符示例或含义
算术+ - * / %n / 10 求整数商，n % 10 求余数
比较== != < <= > >=lives == 0 判断相等
逻辑! && / ||非、两个条件都成立、任一条件成立
位运算& / | / ^ ~ << >>按钮掩码及其他位集合
赋值= += -= 等x += 1 更新数值
自增自减++ --i++ 增加 1
条件选择condition ? A : B根据条件选择一个值
指针&variable / *p取得地址或访问指向的数据

请区分 = 和 ==。复杂表达式用括号写清意图，不要把过多函数调用和副作用挤在一条语句里。避免除以零和数组越界。sizeof 返回字节数，offsetof 返回结构体成员的偏移。

6. 分支与循环

c
if (lives == 0) { game_over = 1; }
else { score = score + 10; }
for (i = 0; i < 4; i++) { table[i] = i; }
while (running != 0) { update_game(); }
do { count++; } while (count < 3);

break 离开循环或 switch，continue 进入下一轮循环，return 结束函数。需要从一个 switch case 继续执行下一个时，请明确写出 fallthrough;；隐式贯穿会触发诊断。完整程序见 gb_control.c。

7. 函数、数组与结构体

c
u8 add(u8 a, u8 b) { return (u8)(a + b); }
typedef struct { u8 x; u8 y; } Point;
Point player;
u8 tiles[4];

数组下标从 0 开始，四元素数组的合法下标为 0～3。player.x 访问成员，pointer->x 通过指针访问成员。解析器接受结构体、联合体和枚举，但布局取决于类型以及 __packed / __aligned 属性。与硬件或二进制格式交换数据前，应检查 sizeof。

默认 Legacy ABI 将参数和局部存储放在固定位置。不要假定具备桌面式递归或中断重入能力。__stackcall 和 --abi=stack 是高级调用约定选项；混用约定时应检查 ABI 报告并验证执行。

8. 多文件与预处理器

类型、常量、声明放在头文件，函数体放在 .c 文件。使用 #pragma once 或头文件保护宏避免重复包含。条件编译支持 #define、#undef、#if、#ifdef、#ifndef、#elif、#else、#endif。

powershell
.\kitaqgb\kitaqgb.exe main.c game.c .\kitaqgb\lib\input.c -I .\kitaqgb\lib -o .\out\game.gb --profile=dev

-I 添加头文件搜索目录。包含头文件并不等于链接实现，还要在构建命令中列出所需 .c 文件。按需选择源文件；把全部库文件无差别加入，可能造成寄存器定义或中断处理程序重复。

9. ROM、内存与分页

ROM 存代码和常量，WRAM 存变量，VRAM 存图像，OAM 存精灵描述。切换 bank 会改变 CPU 地址映射到哪一块实际内存。单独一个 16 位指针无法标识另一 bank 的数据。

c
#pragma bank 1
__prg_rom u8 level_data[] = { 1, 2, 3, 4 };

__prg_rom 将数据放入 ROM；__location(0xFF40) 等属性指定固定地址，__wram / __hram 指定内存区域。使用 #pragma bank 或 #pragma fixed_bank 时，请检查映射文件，确保中断使用的代码和数据始终可访问。

powershell
.\kitaqgb\kitaqgb.exe main.c -o .\out\game.gbc --cart=mbc5 --romsize=256k --ramsize=32k --cgb=cgb --rom-title=MYGAME --stack-bank=fixed --emit-ai-metadata=.\out\build.json

--cgb=dmg 声明 DMG 软件，--cgb=cgb 声明双模式软件，--cgb=cgb_only 声明 CGB 专用软件。双模式游戏必须先识别硬件，再使用 CGB 专用功能。ROM 头标志不会替你实现游戏内部的双模式逻辑。

10. 安全更新图像

VBlank 是显示帧之间的空白期。时机不当的 VRAM/OAM 写入可能导致画面损坏或更新丢失。初始化素材应在关闭显示时加载，常规更新应使用安全内建函数或 VRAM 队列。带 _unsafe、_fast 的函数需要调用方保证安全传输时段。

OAM DMA 缓冲区须按 256 字节边界对齐。GB 的 __oam_dma 接收源地址；FC 的同名内建函数没有参数，二者不能混用。

11. 构建选项与输出文件

-o 选择输出，-O0 / -O1 选择优化级别，--profile=dev|release|test 选择设置组合。--no-disasm 关闭反汇编输出；--debug-out=...、--trace-out=... 指定调查资料的位置。根据快速构建或详细排查的需要选择输出量。

powershell
.\kitaqgb\kitaqgb.exe main.c -I .\kitaqgb\lib -o .\out\game.gb --profile=dev --diag-json=.\out\compile.json --emit-ai-metadata=.\out\build.json --debug-out=.\out\debug

.map 记录名称和布局，.funcsizes.txt 记录函数大小，.dbg2.json / .source_map.txt 关联执行位置与源码，.build_report.json 汇总构建结果。明确生成 --emit-ai-metadata JSON，可使 SARAKURA 的输入关系更清楚。

12. 从第一个错误读起

先读首个错误的文件名、行号和 KQ 诊断编号；后续错误可能只是第一个语法错误的连锁结果。未定义符号应检查声明、实现以及是否加入构建。ROM 超出容量时，检查素材大小、函数大小和 bank 布局。

powershell
.\kitaqgb\kitaqgb.exe kqhelp KQ1002
.\kitaqgb\kitaqgb.exe symfind main --map=.\out\game.map
.\kitaqgb\kitaqgb.exe romdiff .\out\before.gb .\out\after.gb

13. 内联汇编

__asm { ... } 使用 KITAQGB 的指令名称，不保证接受其他 GB 汇编器的任意源码。内部名称包括 LD_A_IMM 等。使用前须了解参数、返回值、需保留的寄存器和栈行为。附录列出了指令写法与操作数格式。

c
void nop_example() {
    __asm { NOP }
}

源码位置

编译器源码和项目文件位于仓库内的同名子目录，可执行文件位于仓库根目录，库文件位于 lib/。项目路径和构建要求请参阅目录结构说明。
