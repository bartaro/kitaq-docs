Verification scope

The records below belong to the September 12 source snapshot. The two compilers and KUROSAKI CLI were built from the collected sources. KOKURA and SARAKURA used local executables fingerprinted in the inventory. These checks do not cover all features, peripherals or physical hardware.

Each entry records compilation, a 120-frame emulator run and its screenshot. Pixel comparisons are separate evidence. Exit code zero alone does not prove correct input, sound or game behavior. Build and runtime evidence is documented in publication checks; test inputs and conditions are recorded there.

API examples: expected images and verification

Each tile program was built and run for 90 frames in KOKURA in both DMG and CGB modes. Verification compares the displayed tile pattern and its blank border against the supplied font, checks the expected foreground colors, and reads the on-screen result. The ROM also reads back the target tile and attribute bytes. A zero exit code alone is not the pass criterion. Writes in these examples occur with the LCD off; hardware behavior and LCD-on transfer timing have not been tested here.

__settile

Write one tile-number byte to the tile map; this selects an existing tile image, not new pixel data.

The destination is always 0x9800 + 32*y + x, regardless of which maps LCDC selects for the background and window.

Expected image: the following tile pattern starts at tile coordinates (x=2, y=3), or pixel coordinates (16,24). Each character occupies one 8×8 tile. Read the pattern from top to bottom and left to right; the surrounding tiles remain blank.
